# 개미 키우기 RPG · 구글 시트 연결

게임 파일과 이 폴더의 `Code.gs`가 한 쌍입니다. 게임의 `src/config.js`에는 전달받은 웹 앱 주소를 넣어 두었습니다. **해당 웹 앱의 Apps Script에 이 코드를 설치하고 새 버전으로 배포해야 계정 가입과 온라인 저장이 작동합니다.** 제작 과정에서는 실제 시트에 테스트 계정을 만들지 않았습니다.

전달받은 `https://script.google.com/macros/s/…/exec` 주소는 저장 요청을 받는 웹 앱 주소입니다. 시트 표를 여는 주소는 해당 구글 스프레드시트의 `https://docs.google.com/spreadsheets/d/…/edit` 주소입니다.

## 1. 코드 넣기

1. 게임 전용 구글 스프레드시트를 엽니다.
2. **확장 프로그램 → Apps Script**를 엽니다.
3. 기존 `Code.gs`에 같은 이름의 `doGet`, `doPost` 함수가 있다면 중복되지 않도록 기존 내용을 이 폴더의 **`Code.gs` 전체 내용**으로 교체합니다.
4. 저장한 뒤 상단 함수 목록에서 **`시트준비`**를 선택하고 **실행**합니다.
5. 본인 구글 계정으로 시트 접근을 허용합니다. 시트에 **플레이어**, **읽어 주세요** 탭이 생성되면 준비가 끝났습니다.

시트에서 열지 않은 독립 Apps Script 프로젝트를 사용한다면 **프로젝트 설정 → 스크립트 속성**에 다음 속성을 추가합니다.

| 속성 | 값 |
|---|---|
| `스프레드시트아이디` | 시트 주소에서 `/d/`와 `/edit` 사이에 있는 문자열 |

시트에서 직접 연 프로젝트는 이 속성 없이 해당 시트를 사용합니다. 시트에 이미 `플레이어`라는 탭이 있고 첫 줄이 게임의 열 구성과 다르면 오류로 알립니다. 기존 표를 덮어쓰지 않으므로 해당 탭의 이름을 바꾼 뒤 `시트준비`를 다시 실행하면 됩니다.

## 2. 웹 앱 배포

**이미 제공한 주소를 유지하려면** Apps Script의 **배포 → 배포 관리 → 해당 웹 앱 수정**으로 들어갑니다. 버전을 **새 버전**으로 선택하고 배포합니다. 코드 저장만으로는 기존 `/exec` 웹 앱에 새 코드가 반영되지 않습니다.

처음 배포한다면 **배포 → 새 배포 → 유형: 웹 앱**을 선택합니다.

| 설정 | 선택 |
|---|---|
| 실행 사용자 | **나** — 시트 소유자 계정 |
| 액세스 권한 | **모든 사용자** — 구글 로그인 없는 사용자 포함 |

회사나 학교 계정 정책 때문에 모든 사용자 공개가 제한되어 있으면 그 계정에서는 외부 플레이어가 접속하지 못할 수 있습니다. 배포 설정의 선택 가능 항목을 먼저 확인해 주세요. 설정 방법은 [Google 공식 웹 앱 문서](https://developers.google.com/apps-script/guides/web)를 참고할 수 있습니다.

새로 배포해서 주소가 달라졌다면 게임의 `src/config.js`에서 `API_URL`을 새 **`/exec` 주소**로 바꿉니다. 편집기 시험용 `/dev` 주소는 사용하지 않습니다.

```js
export const VERSION = '1.0.0';
export const API_URL = '여기에 새 웹 앱의 exec 주소';
```

주소만 브라우저에서 열었을 때 `ok: true`, 게임 이름, 버전이 포함된 응답이 나오면 새 코드가 응답하고 있는 것입니다. 실제 시트 쓰기 권한까지 확인하려면 아래의 게임 가입·저장 확인을 진행합니다.

## 3. GitHub Pages에서 실제 연결 확인

게임 폴더의 배포 방법은 상위 `README.md`를 따릅니다. `index.html`을 파일 탐색기에서 직접 여는 대신 GitHub Pages 또는 로컬 웹 서버로 접속합니다.

1. 게임 가입 화면에서 한글 아이디와 **`0516`** 같은 네 자리 비밀번호로 가입합니다.
2. 설정에서 **즉시 저장**을 누릅니다. 게임에 **온라인 저장 완료**가 표시되는지 확인합니다.
3. 시트의 `네 자리 비밀번호` 값이 **0516**이고, `누적 플레이 초`, `현재 등급`, `진행 중인 임무`가 들어왔는지 확인합니다.
4. 게임에서 1분 이상 플레이하면 누적 시간과 최근 저장 시각이 바뀌어야 합니다.
5. 로그아웃 후 같은 아이디와 `0516`으로 로그인합니다. 진행이 돌아오고 로그인 횟수가 1 증가해야 합니다.
6. 다른 기기에서 같은 계정으로 로그인하면 그 기기가 최신 접속이 됩니다. 이전 기기의 저장은 재로그인 안내와 함께 중단됩니다.

이 검사는 운영자가 배포 후 직접 확인하는 절차입니다. 코드의 자동 테스트는 실제 사용자 시트와 분리된 메모리 시트로 실행됩니다.

## 시트에 표시되는 정보

`플레이어` 탭은 첫 줄과 아이디·비밀번호 열이 고정되고 행이 번갈아 다른 색으로 표시됩니다. 첫 줄의 필터로 아이디를 찾거나 플레이 시간, 로그인 횟수, 등급별로 정렬할 수 있습니다.

| 구분 | 내용 |
|---|---|
| 계정 | 사용자 아이디, 네 자리 비밀번호, 가입 시각, 로그인 횟수 |
| 접속·저장 | 최근 로그인 시각, 최근 저장 시각, 게임 버전, 저장 차수 |
| 시간 | `0시간 30분 00초`처럼 읽기 쉬운 누적 시간, 정렬·계산용 누적 초 |
| 성장 | 등급 이름, 공헌도, 현재 임무 제목과 진행, 완료 임무 수, 클리어 여부, 즉위 시각 |
| 생활 | 자원별 보유량, 채집·굴착·도움·사건 해결 횟수, 발견 기록, 친구 관계, 여왕 생활 |
| 복원 | 한국어 항목으로 작성된 진행 복원 자료, 위치, 동료 수, 굴착조 작업 누적 시간, 소리 설정 |

누적 플레이 시간은 게임의 플레이 중인 시간 기준으로 전달받습니다. 서버는 기존에 저장한 시간보다 작은 수치로 시간을 되돌리지 않습니다. 로그인 횟수는 가입 첫 접속을 포함하고, 같은 요청의 통신 재시도는 중복 집계하지 않습니다.

시트의 **열 제목과 순서**, **진행 복원 자료**, **저장 차수**는 유지해 주세요. 게임 코드와 함께 사용하는 저장 형식입니다. 행 전체를 정렬하는 것은 괜찮습니다.

## 비밀번호 첫 자리 영 보존

요청한 대로 비밀번호는 해시 처리 없이 네 자리 문자열로 저장합니다. 서버는 **셀에 쓰기 전에 텍스트 서식 `@`를 지정**하고 문자열 그대로 씁니다. 브라우저도 비밀번호를 숫자로 변환하지 않습니다.

따라서 `0516`은 `0516`, `0000`은 `0000`으로 저장됩니다. 예전 입력으로 셀에 `516`처럼 남아 있더라도 로그인할 때 네 자리로 보정하며, 로그인 성공 후 텍스트 `0516`으로 바로잡습니다. 비밀번호는 로그인 응답에 포함하지 않고 브라우저의 영구 저장에도 넣지 않습니다. [Google의 셀 표시 형식 문서](https://developers.google.com/apps-script/reference/spreadsheet/range#setNumberFormat(String))

## 연결 실패와 충돌 처리

- **기기에 임시 저장했습니다**: 현재 기기의 브라우저에 진행이 남았습니다. 다음 자동 저장이나 즉시 저장에서 다시 전송합니다.
- **다시 로그인해 주세요**: 다른 기기에서 로그인했거나 서버 저장 차수가 달라졌습니다. 최신 서버 진행을 다시 불러와야 합니다. 오래된 기기의 진행으로 서버를 덮어쓰지 않습니다.
- **진행 상황을 불러올 수 없음**: 가입·로그인이 실패한 경우 체험 계정으로 몰래 전환하지 않습니다. 로컬 체험은 별도의 선택입니다.
- 같은 기기에서 로그인할 때, 보내지 못한 로컬 진행의 기준 저장 차수와 서버 차수가 같으면 로컬 진행을 복원합니다. 서버가 더 최신이면 서버 진행을 우선합니다.
- 브라우저의 사이트 데이터 삭제 또는 다른 브라우저로 이동하면 기기에만 남은 임시 저장은 함께 이동하지 않습니다. 온라인 저장 완료가 표시된 진행은 계정 로그인으로 불러옵니다.

통신은 계정 정보가 주소에 노출되지 않도록 **POST 본문**으로 보냅니다. Apps Script의 `ContentService`는 응답을 `script.googleusercontent.com`으로 리디렉션하므로 클라이언트가 리디렉션을 따라가게 되어 있습니다. `text/plain` 본문으로 보내고 반환된 JSON 응답을 실제로 읽어 성공 여부를 판단합니다. [Google Content Service 문서](https://developers.google.com/apps-script/guides/content#redirects)

`no-cors`로 응답을 읽을 수 없게 하거나 로그인 정보를 JSONP 주소에 붙이는 우회 방식은 사용하지 않습니다. 화면에 성공을 표시하려면 읽을 수 있는 서버 응답이 필요합니다.

## 오류가 계속될 때

| 증상 | 확인할 곳 |
|---|---|
| 서버가 아직 준비되지 않았다는 안내 | 기존 웹 앱에 `Code.gs` 전체를 설치했는지, 새 버전으로 배포했는지 확인 |
| 구글 로그인 화면 또는 권한 오류 | 배포 실행 사용자가 나인지, 액세스 권한이 모든 사용자인지 확인 |
| 시트를 찾지 못함 | 시트에서 연 Apps Script인지, 독립 프로젝트라면 스프레드시트아이디 속성 확인 |
| 서버 응답을 읽지 못함 | `/exec` 주소인지 확인하고 Apps Script 실행 기록에서 실패한 실행 확인 |
| 브라우저 연결·CORS 오류 | GitHub Pages에서 접속했는지, 웹 앱이 로그인 없이 공개됐는지, 브라우저가 구글 저장 도메인을 차단하지 않는지 확인 |
| 수정 코드가 반영되지 않음 | 배포 관리에서 **새 버전**을 선택했는지 확인 |

Apps Script 실행 화면의 오류를 확인할 때 계정 비밀번호와 전체 진행 자료를 공개 게시물에 붙일 필요는 없습니다. 오류 문구와 발생한 함수 이름으로 먼저 확인할 수 있습니다.

## 다음 버전 수정

게임을 업데이트할 때는 `src/config.js`의 `VERSION`과 `Code.gs` 상단 `GAME_VERSION`을 함께 갱신합니다. 저장 자료 항목을 변경한다면 `normalize_`, `encodeState_`, `decodeState_`와 자동 테스트도 함께 수정하고 Apps Script를 새 버전으로 배포합니다. 시트 구조를 유지하는 일반적인 게임 개선은 기존 플레이어 행을 그대로 사용할 수 있습니다.

검증 명령은 게임 폴더에서 실행합니다.

```sh
node --test --test-isolation=none tests/storage.test.mjs tests/apps-script.test.mjs
```
